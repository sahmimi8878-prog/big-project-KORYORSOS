ระบบเอกสาร (ยื่นเอกสารกู้ยืม กยศ.)

อธิบายทั้งระบบตั้งแต่ นักศึกษาแนบไฟล์ → แอป Flutter → server Node.js → ฐานข้อมูล + โฟลเดอร์ไฟล์ จนถึง เจ้าหน้าที่ตรวจและอนุมัติ พร้อมโค้ดจริง ผลทดสอบจริง และจุดที่ควรรู้ก่อนพัฒนาต่อ เขียนให้เพื่อนที่รับผิดชอบระบบนี้อ่านทำความเข้าใจได้ตั้งแต่ต้นจนจบ

วิธีอ่านเอกสารนี้
  • ทุกส่วนมีกล่อง 📍 อยู่ที่ไหน / เรียกมายังไง บอกชื่อไฟล์ ฟังก์ชัน และเส้นทางที่เรียกต่อกัน
  • โค้ดทุกก้อนคัดจากไฟล์จริง เลขทางซ้ายคือเลขบรรทัดในไฟล์ (VS Code กด Ctrl+G แล้วพิมพ์เลขเพื่อไปที่บรรทัดนั้น)
  • ถ้าอ่านครั้งแรก ให้อ่านบท 1 → 2 → 9 (เล่นทีละขั้น) ก่อน แล้วค่อยอ่านรายละเอียดบท 4–8
  • บท 10 รวมข้อสังเกตที่ตรวจพบจากโค้ดและการทดสอบจริง (ไม่ได้แก้อะไรในโปรเจกต์) เพื่อให้รู้ก่อนพัฒนาต่อ
  • ข้อมูลตัวอย่างในเอกสารนี้ปรับชื่อไฟล์/ชื่อนักศึกษาให้ไม่ระบุตัวตนแล้ว (โครงสร้างตรงกับของจริง)

1. ภาพรวมระบบเอกสาร

⚡ สรุป 30 วินาที
  • นักศึกษาแนบไฟล์ 7 ประเภท → เจ้าหน้าที่ตรวจ อนุมัติ/ไม่อนุมัติ
  • เอกสาร 1 ชิ้น = แถวในตาราง documents + ไฟล์ในโฟลเดอร์ uploads/
  • สถานะ: pending → approved / rejected

นักศึกษาต้องส่งเอกสารประกอบการกู้ยืม กยศ. หลายอย่าง ระบบนี้ให้ แนบไฟล์ผ่านแอป แทนการยื่นกระดาษ แล้ว เจ้าหน้าที่ตรวจในแอป ว่า "อนุมัติ" หรือ "ไม่อนุมัติ" นักศึกษาเปิดดูสถานะของตัวเองได้ตลอด

นักศึกษา (role_id = 1)เจ้าหน้าที่ (role_id = 2)
ทำอะไรได้ดูเอกสารของตัวเอง (พร้อมสรุปจำนวนตามสถานะ) · เพิ่มเอกสาร (เลือกไฟล์ตามประเภท ส่งได้หลายประเภทพร้อมกัน) · แก้ไข (เปลี่ยนไฟล์) · ลบดูรายชื่อนักศึกษาที่ส่งเอกสาร (คนที่มีเอกสารรอตรวจขึ้นก่อน) · ค้นหา/กรอง · เปิดดูไฟล์ · อนุมัติ / ไม่อนุมัติ
เห็นข้อมูลของใครเฉพาะของตัวเอง (server กรองด้วย user_id จาก token)ของทุกคน (JOIN ชื่อและรหัสนักศึกษามาด้วย)

1.2 สถาปัตยกรรม: ต่างจากระบบจองตรงที่มี "ไฟล์"

เอกสาร 1 ชิ้น = แถวในตาราง (บอกว่าของใคร ประเภทอะไร สถานะอะไร) + ไฟล์บนดิสก์ (ตัวเอกสารจริง) เชื่อมกันด้วยคอลัมน์ file_path

1.3 สถานะของเอกสาร (status)

สถานะเก็บเป็นข้อความในคอลัมน์ status ค่าที่แอปใช้มี 3 ค่า: pending · approved · rejected

1.4 ภาพรวมการไหลของข้อมูล

  1. นักศึกษา เลือกไฟล์ตามประเภท กด "บันทึก" → แอปส่ง POST /api/documents (แนบไฟล์) → server เก็บไฟล์ลง uploads/ และเพิ่มแถวสถานะ pending
  2. นักศึกษา เห็นเอกสารในรายการ "เอกสารของฉัน" พร้อมป้าย "รอตรวจสอบ" (GET /api/documents)
  3. เจ้าหน้าที่ เปิด "จัดการเอกสาร" → เห็นรายชื่อนักศึกษา (GET /api/officer/documents) กดชื่อ → เห็นเอกสารของคนนั้น → กดเอกสาร → เปิดดูไฟล์ แล้วกดอนุมัติ/ไม่อนุมัติ (PUT …/status)
  4. นักศึกษา เปิดรายการอีกครั้ง ป้ายสถานะเปลี่ยนเป็น "อนุมัติแล้ว" หรือ "ถูกปฏิเสธ"

      เพิ่มเอกสารแล้ว "สำเร็จ" แต่ไม่โผล่ในรายการserver ตอบ 200 + isError (ดูข้อสังเกตข้อ 1) เช่น ฐานข้อมูลปิด/ตาราง documents ผิดดู log ของ server (terminal ที่รัน) และเปิดฐานข้อมูลให้ทำงาน
      เจ้าหน้าที่กด "เปิดดูเอกสาร" แล้วไม่ขึ้น/ว่างURL ไฟล์ผิด (server ไม่ได้รันที่ 127.0.0.1:3000) หรือไฟล์ถูกลบแล้วเช็กค่า serverUrl ใน _openFile และดูว่าไฟล์ยังอยู่ใน uploads/
      build บน Linux/macOS ไม่ผ่านที่ import document_serviceโฟลเดอร์ Service (S ใหญ่) แต่ import ใช้ serviceข้อสังเกตข้อ 9
